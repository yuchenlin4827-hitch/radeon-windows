# 许可证分析

本项目是"Linux 开源栈 → Windows"的移植，天然跨三个许可证域，
**每个源文件必须在文件头标注自己的许可证域**。

## 1. 三方许可证

| 来源 | 许可证 | 义务 |
| --- | --- | --- |
| 本项目新写代码（kmd 骨架、gpu_probe、CI 脚本、文档） | **MIT**（仓库默认） | 保留版权声明即可，可闭源分发 |
| Mesa / terakan | **MIT** | 同上 |
| Linux 内核 radeon/amdgpu | **GPL-2.0**（含仅 GPL-2.0 与 GPL-2.0+ 两种标注） | 衍生作品以 GPL-2.0 分发，**必须提供源码** |

## 2. 混合规则（实践）

1. **逐文件标注入库来源**：
   - 从 `drivers/gpu/drm/radeon/*.c` 移植的寄存器序列、PM4 包定义、
     PCI ID 表等，即使"手抄改写"，在版权意义上是**衍生作品**，
     该文件整体按 GPL-2.0 标注（头部注明上游路径与提交基线）。
   - 只有接口定义、骨架逻辑（对 OS 的 DDI 适配层）才算纯新代码（MIT）。
2. **二进制分发**：`rokmd.sys` 只要含 GPL 衍生段，发布即触发 GPL-2.0 的
   源码提供义务 —— 对本项目（全开源）无冲突，但**不能**作为闭源基础。
3. **用户态/内核态边界不改变许可义务**：UMD 与 KMD 同仓库同项目，混合
   GPL/MIT 是允许的（GPL 段独立成文件），但建议保持目录隔离：
   `kmd/src/hw/`（GPL-2.0 移植段）与 `kmd/src/ddi/`（MIT）分开放。
4. **terakan（MIT）**：可以自由 fork、修改、随自研 KMD 一起分发，无传染性。
5. **商标**：`Radeon`、`AMD` 是 AMD 商标，仓库名/产物命名避免直接冒用
   官方品牌（`rokmd` 这类中性名即为规避）。

## 3. 当前仓库各部分的标注

| 路径 | 许可证 | 说明 |
| --- | --- | --- |
| `kmd/src/*.c(h)` | MIT | 全新骨架，未含内核移植代码 |
| `tests/gpu_probe/*` | MIT | 全新代码 |
| `.github/workflows/*` | MIT | CI 脚本 |
| `docs/*` | MIT | 文档（引用外部内容已标来源） |
| M3 起新增 `kmd/src/hw/` | **GPL-2.0** | radeon 内核驱动移植段（届时建立） |
